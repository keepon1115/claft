# レスポンシブ崩れの直し方ナレッジ（claft-HP 恒久文書）

最終更新: 2026-07-07
このリポジトリで繰り返し起きる「PC/スマホで表示が崩れる・違って見える」問題の
**症状 → 原因 → 直し方** を記録する。新しい類型を直したら、このファイルに追記すること。

## 大原則（3つ）

1. **テキストと飾りの空間を分ける。** 文字が読まれる領域（本文カラム）に、装飾を絶対配置で
   重ねてはいけない。飾りは「本文カラムの外側（レール・背景・カード枠）」で遊ばせる。
2. **「窓の幅」ではなく「カラムの幅」で考える。** Tailwind の `sm:` `lg:` はビューポート幅で
   切り替わるため、「PCの中央 640px カラム」と「640px のスマホ」で別のスタイルが当たる。
   本文カラムの内側（文字サイズ・行間・余白）はブレークポイントで変えないのが基本。
   変えてよいのはカラムの**外側**（レール・カラム数・飾りの有無）だけ。
3. **%座標・ビューポート単位でのピン留めは事故のもと。** `top-[12%]` や `100svh` 基準の配置は
   端末の縦横比で暴れる。要素の位置は原則フロー（flex/grid）で決める。

## 症状別パターン集

### パターン1: 絶対配置の飾り（写真・イラスト）が文字に被る

- **症状**: スマホや中間幅で、浮遊する写真がタイトルや本文に重なって読めない。
- **原因**: `absolute inset-0` ＋ %座標で飾りをセクション全面に配置し、中央テキストと
  同じ空間を取り合っている。`pt-32` のような「余白で避ける」対処は画面比が変わると破綻する。
- **直し方**:
  - スマホ: 絶対配置をやめ、飾りを通常フローの1ブロック（テキストの上か下）に移す。
  - PC: **セーフゾーン式グリッド**にする。中央カラムをテキスト専用にし、飾りは左右レール内にだけ置く。
    ```
    <div class="grid grid-cols-[1fr_minmax(0,42rem)_1fr]">
      <div>…左レール（飾り）…</div>
      <div>…テキスト専用。飾りは構造上入れない…</div>
      <div>…右レール（飾り）…</div>
    </div>
    ```
  - アニメーション（浮遊・回転）はレール内なら維持してよい。
- **実例**: なんでも展示会紹介ページのヒーロー（EXHIBITION_READABILITY_BRIEF.md §2）

### パターン2: PCの中央カラムとスマホが「同じ幅なのに見た目が別物」

- **症状**: PCでウィンドウを狭めた表示とスマホ実機で、同じくらいの幅なのに文字サイズや
  レイアウトが大きく違う。
- **原因**: ビューポート幅ブレークポイント（`sm:` 等）で本文カラムの**内側**まで変えている。
- **直し方**:
  - 本文カラムは `max-w-3xl`（または `max-w-prose`）＋ `mx-auto` で幅を固定し、
    内側のタイポグラフィはブレークポイント分岐を最小にする。
  - 見出しのサイズ差は**1段階まで**（例: `text-4xl sm:text-5xl` は可、`text-4xl sm:text-6xl` は不可）。
  - `hidden sm:block` による出し分けは**純粋な装飾のみ**。情報を持つ要素の出し分けは禁止。
  - 根本対応が必要な場合はコンテナクエリ（`@container` / cqi 単位）を使う。
    サイトの craft デザイントークン（craft-* クラス）は cqi ベースで、vw の clamp は禁止
    （既存規約。docs/ や globals.css の craft トークン定義を参照）。

### パターン3: 100svh・%座標ベースの縦位置が端末で暴れる

- **症状**: あるスマホではちょうど良いのに、別の端末（縦長・横長・ブラウザUIの有無）だと
  要素が上下にずれる・重なる・見切れる。
- **原因**: `min-h-[100svh]` セクション内で `top-[12%]` のような%指定をしている。
  svh はアドレスバーの状態で変わり、%は親の実高さに比例するため二重に不安定。
- **直し方**: 縦位置はフロー＋ `gap` / `py` で決める。「画面いっぱいのヒーロー」が必要でも、
  中身は `flex flex-col justify-center gap-8` のようにフローで並べる。

### パターン4: 長すぎる行・薄すぎる文字で読みにくい

- **症状**: PCで本文が横に伸びて1行60字超になる。補足テキストが薄くて読めない。
- **原因**: 広いセクション枠（`max-w-6xl` 等）に `<p>` を直置き。`text-[#1F1810]/50` のような
  低不透明度を情報テキストに使っている。
- **直し方**:
  - 連続した文章は `max-w-prose`（約65ch ≒ 日本語34字前後）で行長を制限。
    セクション枠が広いのは問題ない（カードグリッド等のため）。文章だけ狭くする。
  - 情報を持つテキストの不透明度は最低 `/70`。`/50` 以下は純粋な飾りラベルにのみ許可。
  - 文章が乗る要素の回転は ±1deg 以内。回転演出は写真・テープ・スタンプに限定。

### パターン5: リンク切れ（`href="#"` の置き忘れ）

- **症状**: ボタンを押しても何も起きない。
- **原因**: デザイン先行で作ったときのプレースホルダー `href="#"` が残っている。
- **直し方**: `grep -rn 'href="#"' app/ components/` で定期的に検出。リンク先が未定なら
  その旨をコメントで明記し、指示書・引き継ぎに「未定」と書く（黙って # のまま出荷しない）。

## 検証チェックリスト（レイアウトを触ったら毎回）

- [ ] **320px / 375px / 768px / 1280px** の4幅で表示確認
- [ ] **PCでウィンドウを640px前後まで狭めた状態**を確認（sm境界直後が一番崩れる）
- [ ] 375px と「PC窓を375px相当に狭めた表示」で本文カラムの見た目が実質同じ
- [ ] どの幅でも、テキストに飾りが被らない
- [ ] どの幅でも、横スクロールが発生しない（`overflow-x` チェック）
- [ ] 長いタイトル・長い作者名を入れても折り返しが破綻しない
- [ ] `prefers-reduced-motion` でアニメーションが止まる
- [ ] `npm run build` が通る
