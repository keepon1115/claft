## §0 コンセプト

> **このページは、島に残してきた「証」を、こちら側から見た記録である。**

企画紹介ページではなく **記録（ログ）** として作る。

| 原則 | 具体化 |
|---|---|
| **① 記録は整えない** | 付箋は原文ママ・誤字ごと・分類ごと。「手が入っていない」ことが伝わる見せ方を選ぶ |
| **② 答えを置かない** | ろ過の順番／クイズの答え／「何が身につくか」——結論を書く場所を**構造から消す**。開く操作・並置・空白で代替する |
| **③ 呼吸させる** | 1セクション＝1メッセージ。詰め込みたくなったら削る |

無人島の世界観は**新色を足さず**、既存クラフト部品のメタファーの読み替えだけで出す：
漂着物＝荷札（`craft-label`）／掟＝立て札／記録＝模造紙の付箋／進行＝5本の刻み。

### 声のトーン

- 過去形の報告。「〜します」ではなく「〜が起きた」。
- 主語は子ども。大人の解釈を足さない。
- 禁止語（実装者が無意識に足しがち）：`力が身につく` `今すぐ` `大人気` `〜な子におすすめ` `学べます` `育みます` `残りわずか`

## §2 デザイン原則（このページの実装ルール）

1. **幅は480px1本**。`.site-main` はPCでも480px固定（「机に貼った1枚の長い紙」）。PC用の別レイアウトを設計しない。「PCで余白が寂しい」と感じても左右に何も足さない（`.site-left` / `.site-right` はサイト共通の担当）。
2. **レイアウトは `mj-` 生CSSで書く**。Tailwindの `sm:grid-cols-*` は PC LAYOUT GUARD（`globals.css` 893-916行）に潰される。折り返しが要る場合は **`@container main (min-width: ...)`** で書く（`@media` を使わない）。
3. **新しい色トークンを `:root` に足さない。** 生hex禁止。透過は `rgb(var(--x-rgb) / 0.12)` 形式。付箋のオレンジのように既存トークンに無い色は、**`mj-` 層内のローカル変数を `color-mix()` で既存トークンから合成**する（§5参照）。
4. **文字サイズは `--text-xs`〜`--text-6xl` のみ**。vwのclampを新規に書かない。見出しのサイズ差は1段階まで。
5. **回転は用途で上限が違う**：文章が乗る要素（付箋・タグ・カード）は **±1deg**。写真・テープ・スタンプは ±3deg まで。`--rot` はインラインstyleで `.craft-tilt` に渡す既存流儀に従う。
6. **情報テキストに `opacity` を使わない。** 2〜5日目の「まだ来ていない感」は、`opacity: .45` ではなく **`color: var(--ink-500)` ＋ `--paper-warm` 面 ＋「予定」ラベル**で作る。`blur` も禁止（読めそうで読めない状態は不快）。
7. **アクセント緑は「線・番号・テープ」に。面の主役にしない。** 本文文字色は `--ink-800/900`。
8. **手描き要素は控えめに。** `components/craft/HandDrawn.tsx` の `Underline` / `ArrowDownDoodle` 程度。`DoodleIcon` は使わない（写真と付箋が主役の記録ページで、汎用ピクトが混ざると密度が落ちる）。**絵文字を装飾に使わない。**
9. 出現アニメは `.reveal` クラスを付けるだけ（`SiteGrid`のグローバルIntersectionObserver任せ）。**独自のIntersectionObserverを書かない。**
10. レイアウト崩れの対処は `docs/RESPONSIVE_DESIGN_KNOWLEDGE.md` を先に読む。

**表示順**：付箋は3色を **決定的なラウンドロビン**(黄→緑→オレンジ→黄…)で混ぜた配列を `NOTES_ORDERED` としてエクスポートする。
理由は2つ — ①色ごとに固めると3つの塊に見えて「壁一面」の密度が落ちる ②`Math.random()` はSSR/CSRで結果がずれてhydration mismatchになる。

```ts
function interleaveByColor(notes: { color: NoteColor; text: string }[]) {
  const order: NoteColor[] = ['yellow', 'green', 'orange'];
  const buckets = order.map((c) => notes.filter((n) => n.color === c));
  const result: typeof notes = [];
  let i = 0;
  while (result.length < notes.length) {
    const bucket = buckets[i % order.length];
    const item = bucket.shift();
    if (item) result.push(item);
    i++;
  }
  return result;
}

export const NOTES_ORDERED = interleaveByColor(NOTES);
```

### §3-3 `MjFigure`(画像待ちで実装を止めない仕組み)

```tsx
type Props = {
  src?: string;        // 未入稿なら省略 → プレースホルダ
  alt: string;         // 必須。プレースホルダのときも書かせる
  need: string;        // 必要な画像の説明。プレースホルダに表示される
  caption?: string;
  width: number; height: number;   // ImagePlaceholder が要求
};
```

- 中身は `components/monthly/ImagePlaceholder.tsx` に委譲。`src` 未指定のときは `caption` に `【要画像】${need}` を流し込み、開発中に不足画像が一目で分かるようにする。
- `alt` を必須propsにすることで、成功基準「画像すべてに適切なalt」を**型で担保**する。
- 装飾的な画像(雰囲気写真)は `alt=""` を明示的に渡す。

### §3-4 画像の扱い(重要な但し書き)

元指示書には「Next.js の Image コンポーネントで最適化する」とあるが、**このリポジトリは `next.config.mjs` で `images: { unoptimized: true }` を設定しており、Next.js側の最適化は効かない**。

したがって：

- `<Image>` は使う(`width`/`height` によるCLS防止と `loading="lazy"` の恩恵は残る)
- **最適化は入稿時に人力で行う**：横幅 **960px**(480pxカラムの2倍)にリサイズ、WebP、1枚 150KB 以下を目安。
- ヒーロー画像のみ `priority`。それ以外は付けない。

### E｜子どもたちのことば(`mj-notes`)← 最重要

- 見出し：**ふりかえりに、こう書いてあった**
- リード(**54字**)：

- 枚数表示：`全25枚`(黄8／緑8／オレンジ9)とだけ。**「たくさんの声！」のような形容をしない。**
- 凡例(付箋ウォールの直前)：黄＝きづいたこと／緑＝ぎもんにおもったこと／オレンジ＝くふうしたこと

- **レイアウト：付箋ウォール(ページ最大の面積)**

  ```css
  .mj-notewall { column-count: 2; column-gap: .6rem; }
  @container main (min-width: 440px) { .mj-notewall { column-count: 3; } }
  .mj-note { break-inside: avoid; display: inline-block; width: 100%; margin-bottom: .6rem; }
  ```

  - **`column-count` を使う理由**：付箋の高さがバラバラのまま隙間なく詰まるから。gridだと行の高さが揃って「模造紙に貼った感じ」が消える。

## §10 やってはいけないこと(最終確認用)

実装後、以下に2つ以上該当したらそのセクションは作り直し。

**サイト共通のアンチテンプレ**
- ダーク背景／青系テックグラデ／波型・斜めカットのセクション区切り
- 「見出し＋抽象イラスト＋CTA」の判で押したヒーロー
- 汎用ピクトグラムの多用／絵文字の装飾使用
- 完璧すぎる均一レイアウト(微小な傾き・余白のゆらぎを1〜2箇所残す)

**このページ固有の禁止(＝整えたくなる衝動のリスト)**
- 付箋の誤字・表記ゆれ・ひらがなを直した
- 付箋の分類を「内容に合うように」動かした
- ろ過の正しい層順を書いた／注記した／「一般的には」と補足した
- クイズの答えを初期表示した
- 2日目以降の内容を確定情報として書いた
- 「◯◯力が身につく」「創造力が育つ」等の効能を書いた
- 子どもの名前をキャプションに足した
- 説明文を150字より長くした
- 指示書にないセクション・文言・画像を追加した

> **迷ったときの判断基準**
> ・説明文と子どもの言葉が競合したら、**子どもの言葉を優先**する
> ・情報量と読みやすさが衝突したら、**読みやすさ**を取る
> ・「わかりやすく整えたい」衝動が起きたら、**やめる**
> ・画像が無ければプレースホルダで進める。**画像待ちで実装を止めない**
> ・迷ったら、**余白を多く取る**
