## 課題① TOPヒーローのキャッチコピー刷新【決定待ち：A/B/C から選択】

### 現状の問題（感覚語「微妙」の翻訳）

対象: `components/Hero.tsx` ①〜②、globals.css `.hp-hero-*`（1709行付近〜）

1. **意味の分散**: H1『"自分で" つくろ！』に目的語がなく、「何を」は小さな荷札
   「自分のキャリア」に隔離されている。H1だけ読むと工作教室に見える。
2. **紙片の渋滞**: 荷札2枚＋H1紙片2枚＝計4枚が縦積みで、視線の起点が定まらない。
   荷札2枚はサイズ・トーンがほぼ同じで階層がない。
3. **半角ダブルクォート `"自分で"`**: 日本語組版で弱く、仮置き感・AI感が出る。
   強調するなら蛍光マーカー風ハイライトや版ずれ（craft-misprint）等、craft の
   語彙でやるべき。
4. **ブランド人格「問いで話す人」がヒーローに不在**（keepon-brand §0）。

### 共通のデザイン修正（どの案でも実施）

- ヒーロー内の「紙」を最大2枚（荷札1＋H1紙片1〜2）まで減らす。
- 引用符による強調は廃止。強調は次のいずれかで置換:
  - 蛍光マーカー風ハイライト（craft の質感トークンで新規 `.craft-marker` を作る場合は
    globals.css の共通部品レイヤーへ）
  - `craft-misprint`（版ずれ）
  - 手描きアンダーライン（`components/craft/HandDrawn` の `Underline`）
- H1のフォントサイズ・紙片スタイル（`--tex-grain`・`--shadow-paper`）は現行を継承。

### 案A（推奨）: 宣言型 「キャリアは、自分でつくれる。」

- 荷札（1枚のみ）: `勉強だけが、ものさしじゃない。`（現行文言を継続）
- H1（紙片2行）: `キャリアは、` ／ `自分でつくれる。`
  - 「自分で」にマーカーハイライト＋`--brand-deep` 文字色（現行2行目の配色を継承）
- 推す理由: ロゴのタグライン「自分でつくるキャリア」と完全に韻が揃い、
  現H1の目的語欠落を最小の変更で解消。命令形→可能形にすることで
  「押し付けない」人格（keepon-brand §0-1）にも寄る。保護者・子どもの両方に同じ
  一文が機能する。

### 案B: 問いかけ型 「きみは、なにをつくる？」

- 荷札: `勉強だけが、ものさしじゃない。`
- H1（紙片2行）: `きみは、` ／ `なにをつくる？`（2行目に手描きアンダーライン）
- H1直下に小さなステッカー1枚: `マイクラも、英語も、対話も。その先に、自分のキャリア。`
- 推す理由: ブランドの核「問いで話す人」をヒーローに実装する最も大胆な案。
  キャリア専業に見えず、マイクラ・英会話など全コースを包含できる。
- 注意: 抽象度が上がるため、直下のリード文（現行④）を必ず残して受け止めること。

### 案C: 昇格型 「勉強だけが、ものさしじゃない。」をH1に

- 荷札は廃止し、いま荷札にある一番強い言葉をH1へ昇格。
- H1（紙片2行）: `勉強だけが、` ／ `ものさしじゃない。`
  - 「ものさし」の脇に手描きの定規ドゥードル（DoodleIcon 新規 or HandDrawn 追加）、
    「じゃない。」に赤鉛筆風の傾き・取り消し線的な遊び。
- H1直下にステッカー: `好きなことが、キャリアになる。`
- 推す理由: 保護者の囚われ（成績・偏差値）を最初の1秒でほぐす。
  「囚われを疑う」人格軸そのもので、SNS/検索で引用されやすい一文。
- 注意: 否定形で始まるため、肯定への折り返し（ステッカー）を必ずセットで。

> どの案でも、⑤信頼チップ・⑥CtaPair・⑦hope リンク・⑧scroll誘導は現状維持。

## 課題② 追従CTAのLINE一本化（PC・スマホ共通）【選択不要・実装可】

### 現状（バグ含む）

- `components/ReserveCTA.tsx`: 「LINEで相談」＋「無料体験を予約」の2ボタンが
  fixed 右下（`.reserve-cta-group`、globals.css 5205行付近、z-index 1200）。
- `components/SiteGrid.tsx` 66〜73行: **直書きのLINE FAB がモバイルで別途レンダリング
  されている**（`.fab`、z-index 60、同じ right/bottom 16px）。ReserveCTA の背面に
  完全に隠れて見えないが、DOMには存在＝スクリーンリーダー・Tab順では LINE ボタンが
  2つある状態。しかもこの FAB には GA 計測（trackEvent）がない。隠れた重複であり削除対象。

### 実装指示

1. `components/SiteGrid.tsx`: 直書き FAB ブロック（`{!pathname?.startsWith('/sogo-senbatsu') && (...)}`
   の `.fab` 一式）を**削除**。
2. globals.css: `.fab` 関連スタイル（547〜570行付近、および PC ガード内の
   `.fab { display:none !important }` 1012行付近）を削除。
3. `components/ReserveCTA.tsx`: 「無料体験を予約」の `<Link>` を削除し、LINEボタン
   のみに。あわせて:
   - 絵文字 `💬` をやめ、`CtaPair.tsx` にあるLINEロゴSVGを共用化して使う
     （絵文字ボタンは keepon-designer アンチパターン「絵文字過多」に該当）。
   - サイズは現行の主ボタン相当に戻す（いまの `--line` 修飾は「従属サイズ」なので、
     一本化後は `padding: 12px 18px` / `font-size: 15px` 相当に）。
   - `trackEvent('cta_line_click', { location: 'reserve-cta', from: pathname })` は維持。
   - `HIDE_ON`（/contact・/admin・/author・/sogo-senbatsu）は現状維持。
4. ページ内の `CtaPair`（LINE｜体験の並列2択）は**変更しない**。体験CVの入口は
   ヒーロー・診断・FlowApply 等ページ内に残る設計。
5. 認識しておくこと: GA4 の `cta_taiken_click` (location='reserve-cta') と
   `reserve_cta_click` イベントは今後発火しなくなる。レポート側で見ている場合は注意。

## 課題③ コース構造のIA整理【決定待ち：D の実施範囲】

### 現状のねじれ（事実関係）

- **商品（申込単位のコース）**: マイクラSDGs ／ キャリア ／ 英会話×STEAM ／ 英会話HelloKiwi（外部）
  （単一ソース: `lib/courses.ts`）
- **学び（プログラム）**: PBL・Yononaka・ミライクラフト・ジブンクラフト
  ＝ **キャリアコースの中身4つ**（TOP `components/ProgramsScrapbook.tsx` の4カード）
- さらに **Yononaka・ミライクラフトは、どのコースの生徒も参加できる**（共通プログラム）。
- ところがサイト上は:
  - キャリアコースに専用ページがなく、`lib/courses.ts:60` の `link: '/jibun-craft'` で
    構成要素の1つに直リンク → 「キャリアコース＝ジブンクラフト？」と誤読させる。
  - Course 構造化データ（coursesJsonLd）の url も /jibun-craft になっており、
    **AI検索がこの誤読を学習する**。
  - ナビ（`lib/nav.ts`）は学び4つがトップレベル、「コース・料金」の子には
    マイクラ・英会話系のみでキャリアコースが不在。商品と中身の階層が逆転。
  - TOP「CLAFTの学び」セクションはコース文脈と未接続（この4つが1コースである
    ことも、2つが全コース共通であることも書かれていない）。

### 提案する整理モデル: 「コース（選び方）」と「学び（中身）」の2層を明示

**Phase 1（推奨・即実施）— キャリアコースのハブページ `/career` 新設**

- `app/(site)/(hidden)/career/` に旧「クエストPBLコース」ページが隠れている。
  これを**craft部品で全面刷新して公開ルートへ移動**（(hidden) から外す）。
- 構成案（cd-* 共通レイヤーを流用）:
  1. ヒーロー: コース名・対象（中学生〜）・月額 ¥7,700〜・「4つの学びがぜんぶ入り」
  2. **4つの学びの循環図**: 探究(PBL)→対話(Yononaka)→実践(ミライクラフト)→
     自己理解(ジブンクラフト)→また探究へ…をスクラップブック/手描き矢印で。
     各カードから既存の詳細ページへリンク。
  3. 料金・FlowApply・CtaPair。
- `lib/courses.ts` の career の `link` を `/career` へ変更（表示と構造化データが
  同時に直る）。sitemap（`app/sitemap.ts` STATIC_PATHS）へ `/career` を追加し、
  robots の (hidden) 除外から外れることを確認。
- 旧ページの文言「クエストPBLコース」は全廃（旧名称の遺物）。

**Phase 2 — /courses に「コース×学び」対応マトリクスを追加**

- `lib/courses.ts` に `includes?: ProgramId[]`（カリキュラムに含む）と
  `openPrograms?: ProgramId[]`（イベント参加OK）を追加し、プログラム定義
  （現在 ProgramsScrapbook.tsx にハードコード）を `lib/programs.ts` として単一ソース化。
- /courses のカード群の下に表を1枚（craft-paper）:
  行＝4つの学び、列＝コース。凡例「◎＝カリキュラムに含む ／ ○＝どのコースでも参加OK」。
  キャリア列は4つ全て◎、マイクラ・英会話×STEAM列は Yononaka・ミライクラフトに○。
- キャリアコースのカードには含まれる学び4つの色チップを表示（「全部入り」バッジの
  根拠が見える化される。CoursePriceGlance の「全部入り」バッジとも整合）。

**Phase 3 — 各学びページとTOPに所属表示**

- /pbl・/yononaka・/futurecraft・/jibun-craft のヒーローに荷札バッジ
  「キャリアコースの学び」＋ /yononaka・/futurecraft にはスタンプ
  「どのコースの方も参加できます」。
- TOP `ProgramsScrapbook` のセクションリードに1行追加:
  「この4つは、キャリアコースにぜんぶ入っています。Yononakaとミライクラフトは、
  どのコースからでも参加できます。」＋ セクション末に「キャリアコースを見る →/career」
  ステッカーを追加。

**D（決定待ち・影響大）— ナビ再編**

- 案D-1: `lib/nav.ts` の「コース・料金」の子に「キャリアコース → /career」を追加するだけ（最小）。
- 案D-2: 学び4項目（PBL/Yononaka/ミライクラフト/ジブンクラフト）を
  「キャリアコースの学び」という見出しグループの下に束ねる（IAとして正しいが、
  ナビの見た目・慣れへの影響が大きい）。
- 推奨は **D-1を先行**、D-2は /career 公開後の反応を見て判断。

**補足（オーナー判断・任意）**: 学び4つのアクセント色は現在
PBL=ピンク／Yononaka=ティール／ミライ=アンバー／ジブン=紫。ブランドの
「色の家族体系」（探究=水色・対話=オレンジ・実践=紫・自己理解=緑）とズレている。
揃えるなら小冊子の正式値で一括変更（keepon-tokens の ★暫定値の確定とセット）。
今回のスコープに含めなくてよい。
