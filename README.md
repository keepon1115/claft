# CLAFT 公式ホームページ（claft-HP）

CLAFT の公式ホームページのためのリポジトリです。活動紹介、コース案内、イベント情報、問い合わせ導線をわかりやすく発信することを目的としています。サイトはモバイル優先で設計し、PC では左にグローバルメニュー、中央にページ本体、右にアカウントやショートカットを配置する三カラム構成です。

## 教育理念とブランドの一貫性

CLAFT は、探究、対話、実践、共創を大切にしています。本サイトでは、情報構造の明快さ、やさしい語り口、迷わない導線設計を通して、理念に沿った体験を提供します。読みやすさと更新しやすさを両立し、関わる全員で継続的に育てていけるメディアを目指します。

## ディレクトリ構成と役割

- ルート直下の HTML（例：`index.html`, `about.html` など）  
  各ページ本体。基本レイアウトは `page` レイアウトを使用します。
- `_layouts/`  
  ページ全体の骨組みを定義します。ヘッダー、フッター、三カラムのグリッド構成など。標準は `page.html` です。
- `_includes/`  
  ヘッダー、フッター、メタ、サイドバーなどの共通断片を配置します。ヘッダーにはモバイル用ドロワー、サイドバーにはグローバルメニューを持ちます。
- `_data/`  
  `nav.yml` にグローバルナビの構造を定義します。ラベル、URL、外部リンクの有無、階層（children）、装飾バリアントなどを扱います。
- `_pages/`  
  追加の固定ページ置き場。必要に応じて使用します。
- `assets/`  
  画像、CSS、JS、PDF などの共有アセット。カテゴリ別に整理します。全体スタイルは `assets/css/site.css`、インタラクションは `assets/js/site.js` にまとめます。
- `_site/`  
  ビルド済みの出力先です。生成物のため手動編集は行いません。
- `Gemfile`, `Gemfile.lock`  
  Jekyll によるビルド環境の管理に使用します。

## ページ一覧（意図と内容の概要）

- `index.html`  
  トップページ。CLAFT の全体像と主要導線（体験申込など）への案内。
- `about.html`（および `about/` 配下）  
  CLAFT の紹介、価値観、学び方。理念をビジュアルとテキストで伝えます。
- `career.html`  
  キャリアに関する学びや成果の紹介。実例や写真を中心に構成します。
- `futurecraft.html`  
  Futurecraft 活動の紹介。イベント、発表、関連リンクなど。
- `minecraft.html`  
  マインクラフトを用いた学びの紹介。活動写真や成果物の抜粋。
- `play-claft.html`  
  PLAY CLAFT（スクールフェスタ計画）の記録。ステップごとの進捗と概要。
- `school_society.html`  
  学校と社会をつなぐ活動の紹介。学びの循環や取り組みの全体像。
- `yononaka.html`  
  Yononaka（世の中）に関する活動の紹介。ワークや成果例。
- `workshop.html`  
  ワークショップ情報のまとめ。参加方法や内容の見取り図。
- `robopro.html`  
  ロボプロ関連の紹介ページ。
- `contact.html`  
  問い合わせ導線。外部フォームや連絡手段へのリンクをまとめます。

必要に応じてページは追加可能です。ナビゲーションの更新を合わせて行います。

## 開発・運用ルール

### ローカル確認

- Ruby と Bundler を準備します。
- 依存関係をインストール後、ローカルサーバーを起動してプレビューします。
- Windows では PowerShell 等のシェルから操作します。

### ビルドと出力

- Jekyll により `_site` フォルダへ出力されます。
- `_site` は生成物のため、直接編集は行いません。

### 更新フロー

1. 変更内容を整理し、対象ファイルを特定します（本文、画像、ナビ等）。
2. 画像や PDF は `assets/` 内の該当カテゴリに保存します（既存の分類に従います）。
3. 新規ページを追加する場合は、ルート直下または `_pages` に作成し、レイアウトとメタ情報（タイトル、説明）を設定します。
4. ナビゲーションの変更は `_data/nav.yml` を更新します。
5. ローカルで表示崩れ、リンク切れ、メタ情報を確認します。
6. コミットしてプッシュします（レビュー運用がある場合はプルリクエストを作成）。
7. 反映後に最終確認を行います。

### 命名規則とファイル運用

- ファイル名・ディレクトリ名は英小文字とハイフンで表記します。
- 画像はページやカテゴリごとにフォルダを分けて保存します。
- 代替テキストは内容が伝わる文章にします。
- 大容量画像は適切に圧縮し、用途に応じた解像度に最適化します。

### 品質とアクセシビリティ

- 見出し階層、リンクテキスト、ラベルの明確さを重視します。
- 主要導線（体験申込、問い合わせ）は常に分かりやすく配置します。
- カラーコントラストやキーボード操作に配慮します。

### SEO とメタ情報

- 各ページのタイトルと説明を適切に設定します。
- ヒーロー画像や要約が明確になるように本文冒頭を整えます。

## デザインルール

### レイアウトとレスポンシブ

- モバイル優先で設計し、モバイルでは一カラム、ドロワーメニューで操作します。
- PC（幅 1024px 以上）では三カラム構成です。
  - 左 240px：グローバルメニュー。スクロール追従で、内部スクロールを許可します。
  - 中央 可変：ページ本文。
  - 右 72px：アカウントやショートカットの縦アイコン。スクロール追従で表示します。
- スクロール追従の基準は上 16px とし、ビューポート高に応じてはみ出し時は内部スクロールを許可します。

### ブランドカラーとタイポグラフィ

- ブランドカラーはティール系を基調に、補助色としてピンク、クリーム、グリーンを使用します。
- フォントは読みやすさを重視し、日本語に適したサンセリフ系を用います。
- 行間と文字間をやや広めにとり、長文でも読みやすい紙面設計を心がけます。

### コンポーネントの原則

- カード、ボタン、タグなどの角丸や影の強さは一貫させます。
- 画像の標準比率は 16:9 を基本とし、同一セクション内で比率を揃えます。
- セクション間の余白は一定に保ち、読みのリズムを整えます。

### トーンとマナー

- 事実を丁寧に伝え、子どもから保護者、教育関係者までに届く語り口を採用します。
- 探究、対話、実践、共創の姿勢が自然に伝わる表現を心がけます。
